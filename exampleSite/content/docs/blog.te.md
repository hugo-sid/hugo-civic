తేదీ ఉన్న పేజీల విభాగం ఏదైనా వార్తా విభాగంలాగే ప్రవర్తిస్తుంది — దాని కోసం
ప్రత్యేకంగా ఎంచుకోవలసిన లేఅవుట్ ఏదీ లేదు. ఈ సైట్‌లోని `/news/` విభాగం ఒక
సాధారణ కంటెంట్ డైరెక్టరీయే; కింద ఉన్నదంతా ఫ్రంట్ మేటర్ నుండి, కాన్ఫిగ్ నుండి
వస్తుంది.

## వ్యాసం ఫ్రంట్ మేటర్

```yaml
---
title: "Section 508 audit results published"
date: 2026-06-30
author: "Digital Services"
tags: ["Accessibility", "Performance"]
description: "Findings from the annual audit, with remediation dates."
image: "img/og-news.png"
imageAlt: "Example Agency news"
---
```

`date`, `author`, `tags` శీర్షిక కింద ఒక బైలైన్‌గా రెండర్ అవుతాయి. ప్రతి ఒక్కటీ
ఐచ్ఛికమే; మూడూ లేకపోతే బైలైన్ పూర్తిగా మాయమవుతుంది — అందుకే డాక్యుమెంటేషన్
పేజీలు, ఈ పేజీతో సహా, దానిని చూపవు.

`lastmod` ఒక "నవీకరించబడింది" తేదీని చేరుస్తుంది, కానీ అది నిజంగా `date` కంటే
తరువాతిదైనప్పుడు మాత్రమే. Hugo `lastmod` ను డిఫాల్ట్‌గా `date` కే అమరుస్తుంది,
కాబట్టి మారని పేజీ మౌనంగానే ఉంటుంది.

అంశాలు తమ పద పేజీకి లింక్ అవుతాయి. ఆ లింకులు ఎక్కడికి వెళ్తాయో బైలైన్ కాదు,
వర్గీకరణ నిర్ణయిస్తుంది.

## జాబితా శైలి

ఒక విభాగం తన జాబితా ఎలా రెండర్ కావాలో తన `_index.md` నుండి ఎంచుకుంటుంది:

```yaml
---
title: "News"
collection_variant: "cards"     # "" | condensed | calendar | media | cards
card_grid: "tablet:grid-col-6 desktop:grid-col-4"   # cards only
---
```

`cards` ఒక `usa-card-group` ను రెండర్ చేస్తుంది. ప్రతి పోస్టూ ఒక కార్డ్ అవుతుంది;
అది తన మొదటి ట్యాగ్‌ను కికర్‌గా, ఉంటే తన చిత్రాన్ని, తన వివరణను, తన బైలైన్‌ను
మోసుకొస్తుంది — USWDS తన సొంత సైట్‌లో ఒక వార్తా అంశానికి ఇచ్చే రూపమే ఇది,
కార్డ్ కాంపోనెంట్ ద్వారా చెప్పబడింది. శీర్షిక పోస్టుకు లింక్ అవుతుంది, ఫుటర్
బటన్ అదే లింక్‌ను పునరావృతం చేస్తుంది — శీర్షికతో లేబుల్ చేయబడి, తద్వారా
లింకులను సందర్భం లేకుండా చదివే స్క్రీన్ రీడర్‌కు ఒకేలాంటి "మరింత చదవండి"ల వరుస
ఎదురుపడదు.

మిగతావన్నీ `usa-collection` — డిఫాల్ట్, పొడవైన జాబితాలకు `condensed`, తేదీ
బ్లాక్ కోసం `calendar`, థంబ్‌నెయిల్ కోసం `media`. చిత్రాలున్న చిన్న ఫీడుకు
కార్డులు సరిపోతాయి; వంద ప్రవేశికల దగ్గరా కలెక్షన్ చదవగలిగేలానే ఉంటుంది.

## పేజీల విభజన

జాబితా పేజీలు Hugo యొక్క `[pagination]` సెట్టింగ్ ప్రకారం విభజించబడతాయి:

```toml
[pagination]
  pagerSize = 5
```

ఒక పేజీ కంటే చిన్న విభాగాలు ఎలాంటి నియంత్రణనూ రెండర్ చేయవు, ప్రవేశికలు తమ URL
లను అలాగే ఉంచుకుంటాయి — పేజీల విభజన అనేది చిన్న విభాగం చెల్లించవలసిన ఖర్చు కాదు.
దీన్ని ఆపడానికి `pagerSize` ను ఎక్కువగా అమర్చండి.

## మూడు కాదు, ముందుకు తీసుకెళ్లే ఒకే ఒక బ్లాక్

ఒక వ్యాసం ముందుకు వెళ్లే సరిగ్గా ఒకే ఒక దారితో ముగుస్తుంది: సంబంధిత కంటెంట్
సూచికకు సరిపోలికలు దొరికితే **సంబంధిత కంటెంట్**, దొరకకపోతే **మునుపటి / తదుపరి**.

అది తప్పిపోయిన సౌకర్యం కాదు, ఉద్దేశపూర్వక పరిమితి. ప్రతి తోబుట్టువునూ చూపే సైడ్
నావ్, అవే తోబుట్టువుల నుండి తీసిన మునుపటి/తదుపరి జంట, మళ్లీ వాటి నుండే తీసిన
సంబంధిత జాబితా — ఇవన్నీ కలిపి మూడు రెట్ల నావిగేషన్ కాదు; అది ఒకే నిర్ణయాన్ని
పాఠకుడి ముందు మూడుసార్లు పెట్టడం.

ఈ విభజన కంటెంట్‌ను అనుసరిస్తుంది. తేదీల ఫీడుకు చదవదగిన క్రమం అంటూ ఏదీ లేదు,
కాబట్టి "ఇలాంటివి మరిన్ని" అనేది ఉపయోగకరమైన ప్రతిపాదన; డాక్యుమెంటేషన్ వృక్షం
క్రమబద్ధమైనది, కాబట్టి "వరుసలో తరువాతిది" ఉపయోగకరం. విభాగాలు తమ `_index.md`
నుండి ప్రక్క నావిగేషన్‌ను వదిలేసుకుంటాయి:

```yaml
---
title: "News"
cascade:
  sidenav: false
---
```

డాక్యుమెంటేషన్ విభాగాలు `sidenav` ను అమర్చకుండా వదిలి వృక్షాన్ని ఉంచుకుంటాయి.

## సంబంధిత కంటెంట్

సంబంధిత కంటెంట్‌కు కావలసిన సూచికను థీమ్ కాన్ఫిగ్‌లో కాక **మీ సైట్** కాన్ఫిగ్‌లో
అమర్చాలి: Hugo ఒక అంతర్నిర్మిత `[related]` డిఫాల్ట్‌ను ఇస్తుంది, ఒక థీమ్
కాన్ఫిగ్ దానికి చేర్చగలదే తప్ప దాన్ని ఎప్పటికీ భర్తీ చేయలేదు. కింది బ్లాక్‌ను
మీరు కాపీ చేసుకునే వరకు వ్యాసాలు మునుపటి/తదుపరి లింకులకే పరిమితమవుతాయి.

```toml
[related]
  threshold = 80
  includeNewer = true

  [[related.indices]]
    name = "tags"
    weight = 100
  [[related.indices]]
    name = "date"
    weight = 10
```

`includeNewer = true` ను ఉంచుకోవడం మంచిది. Hugo డిఫాల్ట్ అయిన `false` పాత
పేజీలను మాత్రమే చూస్తుంది; అంటే అత్యంత కొత్త వ్యాసం — సాధారణంగా ఎక్కువమంది
చూసేది — ఎప్పుడూ ఏమీ చూపదు.

## అంశాల పేజీలు

`/tags/` ప్రతి అంశాన్నీ దాని సంఖ్యతో సహా చూపుతుంది; `/tags/accessibility/` దాని
కింద ఉన్న పేజీలను విభజించి చూపుతుంది. రెండూ ఒకే `tags` ఫ్రంట్ మేటర్ నుండే
తయారవుతాయి, రెండూ ట్యాగులకే కాక సైట్ ప్రకటించే ఏ వర్గీకరణకైనా పని చేస్తాయి.

అంశాల సూచికను ఉద్దేశపూర్వకంగానే విభజించలేదు: సంఖ్యలు వేసిన పేజీల్లో చెల్లాచెదురైన
పదజాలం, పాఠకుడు వెతుకుతున్న పదాన్నే దాచేస్తుంది.

## షేర్ చిత్రాలు

సైట్‌కు ఇచ్చే లింకులు ఒక చిత్రంతో ప్రివ్యూ అవుతాయి; ఆ చిత్రం ఈ వరుసలో
ఎంచుకోబడుతుంది:

1. ఫ్రంట్ మేటర్‌లోని `images` — Hugo సంప్రదాయం, ఒక జాబితా, మొదటి ప్రవేశిక గెలుస్తుంది
2. ఫ్రంట్ మేటర్‌లోని `image`
3. `params.uswds.ogImage`, సైట్ అంతటికీ వర్తించే ప్రత్యామ్నాయం

```toml
[params.uswds]
  ogImage = "img/og-default.png"
  ogImageAlt = "Example Agency"
  twitter = "@example_agency"     # optional, adds twitter:site
```

మార్గాలు ముందుగా పేజీ బండిల్ వనరులుగా, ఆ తర్వాత `assets/` గా, ఆ తర్వాత
`static/` గా పరిష్కరించబడతాయి; సంపూర్ణ URL ఉన్నదున్నట్టే వాడబడుతుంది. 1200px
కంటే వెడల్పైన చిత్రాలు చిన్నవి చేయబడతాయి, సిఫారసు చేసిన 1200x630 కు ఎప్పుడూ
కత్తిరించబడవు — ఒక చతురస్ర ముద్ర లేదా నిలువు చిత్రం తన పైభాగాన్ని కోల్పోకుండా
కార్డులో లెటర్‌బాక్స్ అవుతుంది.

## సామగ్రిని ఆపివేయడం

```toml
[params.uswds.article]
  date = true       # byline
  prevNext = true   # the fallback when there is no related content
  related = 3       # how many related pages to list; 0 makes prev/next the
                    # onward block on every page, tagged or not
```

`sidenav` సైట్ పరామితి కాక విభాగాల వారీ ఫ్రంట్ మేటర్‌గా ఉంటుంది, ఎందుకంటే ఒక
సైట్‌కు సాధారణంగా ఒక విభాగంలో వృక్షం, మరో విభాగంలో ఫీడు కావాలి.
