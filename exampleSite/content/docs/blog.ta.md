தேதியிட்ட பக்கங்களைக் கொண்ட எந்தப் பிரிவும் ஒரு செய்திப் பிரிவாகவே செயல்படும் —
தனியாகத் தேர்ந்தெடுக்க வேறொரு வடிவமைப்பு இல்லை. இந்தத் தளத்தின் `/news/` பிரிவு
ஒரு சாதாரண உள்ளடக்கக் கோப்பகம்; கீழே உள்ள அனைத்தும் முன்தகவலிலிருந்தும்
அமைப்புகளிலிருந்தும் வருகின்றன.

## கட்டுரையின் முன்தகவல்

```yaml
---
title: "Section 508 audit results published"
date: 2026-06-30
author: "Digital Services"
tags: ["Accessibility", "Performance"]
description: "Findings from the annual audit, with remediation dates."
image: "img/og-news.png"
imageAlt: "Example Agency news"
---
```

`date`, `author`, `tags` ஆகியவை தலைப்புக்குக் கீழே ஒரு விவரவரியாகத் தோன்றும்.
ஒவ்வொன்றும் விருப்பத்திற்குரியது; மூன்றுமே இல்லாதபோது விவரவரியே மறைந்துவிடும் —
இந்தப் பக்கம் போன்ற ஆவணப் பக்கங்களில் அது தெரியாததற்குக் காரணம் அதுவே.

`lastmod` ஒரு "புதுப்பிக்கப்பட்டது" தேதியைச் சேர்க்கிறது, ஆனால் அது `date` ஐவிட
உண்மையிலேயே பிந்தையதாக இருந்தால் மட்டுமே. Hugo இயல்பாக `lastmod` ஐ `date` ஆகவே
வைக்கிறது, எனவே மாறாத பக்கம் அமைதியாகவே இருக்கும்.

தலைப்புகள் அவற்றின் சொற்பக்கத்திற்கு இணைக்கின்றன. அந்த இணைப்புகள் எங்கே செல்கின்றன
என்பதை விவரவரி அல்ல, வகைப்பாடே தீர்மானிக்கிறது.

## பட்டியல் பாணி

ஒரு பிரிவு தன் பட்டியல் எப்படித் தோன்ற வேண்டும் என்பதைத் தன் `_index.md` இல்
தேர்ந்தெடுக்கிறது:

```yaml
---
title: "News"
collection_variant: "cards"     # "" | condensed | calendar | media | cards
card_grid: "tablet:grid-col-6 desktop:grid-col-4"   # cards only
---
```

`cards` ஒரு `usa-card-group` ஐ உருவாக்குகிறது. ஒவ்வொரு பதிவும் ஒரு அட்டையாகி,
தன் முதல் குறிச்சொல்லை மேல்வரியாகவும், படம் இருந்தால் அதையும், தன் விளக்கத்தையும்,
விவரவரியையும் சுமக்கிறது — USWDS இன் சொந்தத் தளம் ஒரு செய்திக்குத் தரும் அதே
வடிவம், அட்டைக் கூறின் வழியாக. தலைப்பு பதிவுக்கு இணைக்கிறது; அடிப்பகுதிப் பொத்தான்
அதே இணைப்பைத் தலைப்புடன் திரும்பத் தருகிறது, இதனால் இணைப்புகளைத் தனியே படிக்கும்
திரை வாசிப்பான் ஒரே மாதிரியான "மேலும் படிக்க" வரிசையைச் சந்திக்காது.

மற்ற அனைத்தும் `usa-collection`: இயல்பானது, நீண்ட பட்டியல்களுக்கு `condensed`,
தேதித் தொகுதிக்கு `calendar`, சிறு படத்திற்கு `media`. படங்களுடன் கூடிய குறுகிய
ஊட்டத்திற்கு அட்டைகள் பொருந்தும்; நூறு உள்ளீடுகள் இருந்தாலும் தொகுப்பு படிக்கத்
தக்கதாகவே இருக்கும்.

## பக்கமாக்கல்

பட்டியல் பக்கங்கள் Hugo வின் `[pagination]` அமைப்பின்படி பிரிக்கப்படுகின்றன:

```toml
[pagination]
  pagerSize = 5
```

ஒரு பக்கத்திற்கும் குறைவான பிரிவுகள் எந்தக் கட்டுப்பாட்டையும் காட்டுவதில்லை,
உள்ளீடுகளும் தங்கள் URL களைத் தக்கவைக்கின்றன — சிறிய பிரிவு பக்கமாக்கலுக்காக
எதையும் இழப்பதில்லை. இதை நிறுத்த `pagerSize` ஐப் பெரிய எண்ணாக அமையுங்கள்.

## மூன்றல்ல, ஒரே ஒரு அடுத்த வழி

ஒரு கட்டுரை சரியாக ஒரே ஒரு முன்னோக்கிய வழியுடன் முடிகிறது: தொடர்புடைய
உள்ளடக்கக் குறியீடு பொருத்தங்களைக் கண்டறியும்போது **தொடர்புடைய உள்ளடக்கம்**,
கண்டறியாதபோது **முந்தையது / அடுத்தது**.

இது விடுபட்ட வசதி அல்ல, வேண்டுமென்றே வைத்த வரம்பு. ஒவ்வொரு உடன்பிறப்பையும்
பட்டியலிடும் பக்கவாட்டு வழிசெலுத்தல், அதே உடன்பிறப்புகளிலிருந்து எடுத்த
முந்தையது/அடுத்தது இணை, மீண்டும் அவற்றிலிருந்தே எடுத்த தொடர்புப் பட்டியல் —
இவை மூன்று மடங்கு வழிசெலுத்தல் அல்ல; ஒரே முடிவை வாசகரிடம் மூன்று முறை
கேட்பது.

இந்தப் பிரிவினை உள்ளடக்கத்தைப் பின்பற்றுகிறது. தேதியிட்ட ஊட்டத்தில் படிக்கத்தக்க
வரிசை எதுவும் இல்லை, எனவே "இதுபோன்ற மேலும்" என்பதே பயனுள்ள வழங்கல்; ஆவண மரம்
வரிசைப்படுத்தப்பட்டது, எனவே "அடுத்தது" என்பதே. பிரிவுகள் தங்கள் `_index.md`
இலிருந்தே பக்கவாட்டு வழிசெலுத்தலை விலக்கிக்கொள்கின்றன:

```yaml
---
title: "News"
cascade:
  sidenav: false
---
```

ஆவணப் பிரிவுகள் `sidenav` ஐ அமைக்காமல் விட்டு, மரத்தைத் தக்கவைக்கின்றன.

## தொடர்புடைய உள்ளடக்கம்

தொடர்புடைய உள்ளடக்கத்திற்கு ஒரு குறியீடு தேவை, அது தீமின் அமைப்பில் அல்ல
**உங்கள் தளத்தின்** அமைப்பில் இருக்க வேண்டும்: Hugo ஒரு உள்ளமைந்த `[related]`
இயல்பைத் தருகிறது, ஒரு தீமின் அமைப்பு அதனுடன் சேர்க்க மட்டுமே முடியும், மாற்ற
முடியாது. கீழே உள்ள தொகுதியை நகலெடுக்கும் வரை, கட்டுரைகள் முந்தையது/அடுத்தது
இணைப்புகளுக்கே திரும்பும்.

```toml
[related]
  threshold = 80
  includeNewer = true

  [[related.indices]]
    name = "tags"
    weight = 100
  [[related.indices]]
    name = "date"
    weight = 10
```

`includeNewer = true` ஐத் தக்கவைப்பது நல்லது. Hugo வின் இயல்பான `false` பழைய
பக்கங்களை மட்டுமே பார்க்கிறது; அதாவது மிகப் புதிய கட்டுரை — பொதுவாக அதிகம்
பார்க்கப்படுவதும் அதுவே — எதையும் காட்டுவதே இல்லை.

## தலைப்புப் பக்கங்கள்

`/tags/` ஒவ்வொரு தலைப்பையும் அதன் எண்ணிக்கையுடன் பட்டியலிடுகிறது;
`/tags/accessibility/` அதன் கீழ் வரும் பக்கங்களைப் பக்கம் பக்கமாகப்
பட்டியலிடுகிறது. இரண்டுமே அதே `tags` முன்தகவலிலிருந்து உருவாகின்றன, மேலும்
குறிச்சொற்கள் மட்டுமல்லாமல் தளம் அறிவிக்கும் எந்த வகைப்பாட்டுக்கும் இவை
வேலை செய்யும்.

தலைப்பு அட்டவணை வேண்டுமென்றே பக்கம் பக்கமாகப் பிரிக்கப்படவில்லை: எண்ணிடப்பட்ட
பக்கங்களில் சிதறிய சொல்தொகுதி, வாசகர் தேடும் சொல்லையே மறைத்துவிடும்.

## பகிர்வுப் படங்கள்

தளத்தின் இணைப்புகள் ஒரு படத்துடன் முன்னோட்டமாகத் தோன்றும்; அந்தப் படம் இந்த
வரிசையில் தேர்ந்தெடுக்கப்படுகிறது:

1. முன்தகவலில் `images` — Hugo வின் மரபு, ஒரு பட்டியல், முதல் உள்ளீடு வெல்லும்
2. முன்தகவலில் `image`
3. `params.uswds.ogImage`, தளம் முழுவதற்குமான மாற்று

```toml
[params.uswds]
  ogImage = "img/og-default.png"
  ogImageAlt = "Example Agency"
  twitter = "@example_agency"     # optional, adds twitter:site
```

பாதைகள் முதலில் பக்கத் தொகுப்பு வளங்களாகவும், பின் `assets/` இலும், பின்
`static/` இலும் தேடப்படுகின்றன; முழுமையான URL அப்படியே பயன்படுத்தப்படும்.
1200px ஐவிட அகலமான படங்கள் சுருக்கப்படுகின்றன, ஆனால் பரிந்துரைக்கப்பட்ட
1200x630 க்காக ஒருபோதும் வெட்டப்படுவதில்லை — சதுரமான சின்னமோ நெடுவாக்குப்
படமோ, தலையின் பாதியை இழப்பதற்குப் பதிலாக அட்டைக்குள் இடைவெளியுடன் அமரும்.

## தேவையற்றவற்றை நிறுத்துவது

```toml
[params.uswds.article]
  date = true       # byline
  prevNext = true   # the fallback when there is no related content
  related = 3       # how many related pages to list; 0 makes prev/next the
                    # onward block on every page, tagged or not
```

`sidenav` தள அளபுரு அல்ல, ஒவ்வொரு பிரிவின் முன்தகவல் — ஏனெனில் ஒரு தளத்திற்கு
வழக்கமாக ஒரு பிரிவில் மரமும் இன்னொரு பிரிவில் ஊட்டமும் தேவைப்படும்.
